# Правка текста

Canvas `roll-editor`: сессия кампании показывает в нём предложенную правку
куска документа волта, а Мастер принимает один из вариантов или
отклоняет. Принятый вариант сразу пишется в файл. Пользуется им сессия
правки текста; договор с её стороны записан в скилле
`campaign-proofreading` кампании.

Подключается той же командой, что и пульт: `Install-RollPanel` кладёт в
`~/.copilot/extensions` заглушки обоих canvas. Canvas появляется в
сессиях, начатых после установки.

## Файлы

- `extension.mjs` - объявление canvas и действий. Рантайм читает его один
  раз при старте сессии; после правки нужна новая сессия или
  `extensions_reload`.
- `logic.mjs` - действия, запись в файл, сообщения в сессию.
  Перечитывается при каждом изменении.
- `editor.html` - страница. Отдаётся заново на каждый запрос.
- `pick.mjs`, `pick.html` - второй canvas того же расширения, «Выбор
  вариантов» (ниже). Сервер у них общий, страница выбора живёт под `/pick`.
- `look.mjs`, `look.html` - третий, «Сравнение картинок» (ниже), под `/look`.

## Действия

- `propose { file, original, variants: [{ text, note? }], comment? }` -
  показать правку. `original` - кусок файла байт в байт: абзац или раздел
  из нескольких абзацев. Вариантов от одного до трёх, первый основной.
  Если куска в файле нет или он там не один, действие падает с кодом
  `not_found` или `ambiguous` и прежнюю правку не трогает. Новая правка
  заменяет прежнюю.
- `status` - последняя правка и её состояние: `ждёт`, `принята` (поле
  `variant`, с единицы), `отклонена`, `устарела` (поле `reason`), `пусто`.

## Что делают кнопки

- «Принять»: файл перечитывается, кусок должен встретиться ровно один
  раз. Тогда он заменяется, и файл пишется в UTF-8 без BOM. Окончания
  строк берутся из файла: сессия присылает текст с `\n`, а в CRLF-файле он
  приводится к CRLF. Иначе файл не трогается, правка `устарела`.
- «Не принимать»: правка `отклонена`.
- «Очистить»: правка убирается с панели, состояние становится `пусто`.
  Если по правке ещё не решили, сессия получает об этом сообщение.
- «Проверь, что я пишу»: просьба в сессию найти свежий абзац.

О каждом решении расширение пишет в сессию сообщение через
`session.send`, с приставкой `[Правка текста]`. Сообщение приходит
как реплика пользователя.

Правка хранится в `roll-editor.json` в папке сессии, поэтому переживает
перезагрузку страницы и расширения. У каждой сессии своя правка.

# Выбор вариантов

Canvas `roll-pick`: таблица строк, у каждой несколько вариантов, например
глоссарий перевода. Мастер на каждой строке выбирает вариант одним кликом,
пишет свой или помечает «обсудить» с вопросом, и отправляет всё разом.
Клики сохраняются сразу в `roll-pick.json` папки сессии, так что
перезагрузка страницы выбор не теряет. Рекомендованный вариант обведён
пунктиром, но не выбран. Галочка «только нерешённые» прячет готовые строки.

## Действия

- `propose { title, rows?, tsv?, group? }` - показать порцию, прежняя
  заменяется. Строка: `{ id?, term, variants: [..], comment?,
  recommended?, note? }`, `recommended` - номер варианта с нуля или его
  текст. Вместо `rows` или вместе с ними можно дать `tsv`: путь к TSV
  (UTF-8, TAB) с колонками `term`, `variants` (через `; `), `comment` и
  необязательными `id`, `recommended`, `group`, `category`, `book`; из
  трёх последних собирается подпись под термином. `group` отбирает строки
  TSV по колонке group. Без `id` строка опознаётся по `term`.
- `status` - `{ title, state: ждёт|отправлена|пусто, done, total, out,
  decisions }`; в `decisions` только строки с решением или комментарием.

## Отправка

Кнопка «Отправить» (с подтверждением, если остались нерешённые строки)
пишет TSV `id term decision text remark` в `files\roll-pick-<время>.tsv`
папки сессии и шлёт в сессию сообщение:

```
[Выбор вариантов] Мастер отправил «Глоссарий: canon»: решено 3 из 4, файл C:\...\roll-pick-....tsv.
- Emperor → Бог-Император
- Ordos → свой: «Ордосы»
- Explicator → обсудить: термин из новой редакции?
- Servitor → без решения
```

`decision` в файле: `вариант N` (с единицы), `свой`, `обсудить`, `нет`.
Комментарий Мастера к выбранному варианту идёт в скобках после него.
После отправки порция заперта; следующая приходит новым `propose`.

# Сравнение картинок

Canvas `roll-look`: крупное сравнение вариантов картинок по группам, по
группе на кадр. На каждую картинку «нравится» или «не нравится» и
комментарий, на группу общий комментарий. Картинки по одной или по две в
ряд, фон под ними шахматка, тёмный или светлый: у печатей прозрачный фон,
и на шахматке видны края. Клик по картинке открывает её на весь экран,
стрелки листают по всем группам, там же оценка и комментарий, Esc
закрывает.

Состояние своё у каждого `instanceId` и лежит в `roll-look-<instanceId>.json`
папки сессии: можно открывать по панели на круг. Клики сохраняются сразу.
Страница видит только картинки своего круга, по номерам группы и файла,
произвольный путь с диска через неё не достать.

## Действия

- `propose { title, groups: [{ name, images: [полные пути], note? }] }` -
  показать круг; прежний круг этого instanceId заменяется. Файлы PNG, JPG
  или WebP, все должны существовать, иначе ошибка `no_file`.
- `status` - `{ title, state: ждёт|отправлен|пусто, out, groups: [{ name,
  comment, images: [{ file, path, rating, comment }] }] }`, `rating` -
  `нравится`, `не нравится` или `без оценки`.

## Отправка

«Отправить» (с подтверждением, если остались неоценённые) пишет TSV
`group file rating comment path` в `files\roll-look-<instanceId>-<время>.tsv`
папки сессии; строка группы с пустым file и rating `группа` несёт общий
комментарий. В сессию уходит сообщение:

```
[Сравнение картинок] Мастер отправил «Пробный круг»: оценено 3 из 9, файл C:\...\roll-look-....tsv.
## Дверь: нужен ракурс пониже
- ga6a.png → нравится
- ga6b.png → не нравится: лишняя рука у оборотня
- ga6c.png → без оценки
```

После отправки круг заперт; следующий приходит новым `propose`.
