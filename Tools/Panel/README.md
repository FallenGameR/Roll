# Пульт Roll

Canvas-расширение Copilot: панель с кнопками для страницы плейлиста Winamp, бросков кубиков и голосовой диктовки. Инструменты сами живут в модуле Roll, пульт только вызывает их команды.

## Установка

```powershell
Install-RollPanel
```

Команда кладёт в `~/.copilot/extensions/roll-panel` заглушку из одной строки, которая импортирует `Tools\Panel\extension.mjs` из модуля. В заглушке записан полный путь к модулю, поэтому на новом компьютере и после переноса модуля команду запускают заново.

Copilot подключает расширения при старте сессии. Пульт появится в сессиях, открытых после установки; в уже идущей его не будет. Открыть его можно просьбой "открой пульт".

## Файлы

- `extension.mjs` - объявление canvas и список действий для агента. Рантайм читает его один раз, при старте сессии.
- `logic.mjs` - вся работа: статус, запуск и остановка, журнал диктовки, броски. Перечитывается при каждом изменении файла.
- `panel.html` - страница пульта. Читается заново при каждом открытии страницы.

## Как править

| Что меняется | Где | Что сделать после правки |
| --- | --- | --- |
| Вид, кнопки, порядок секций | `panel.html` | обновить страницу пульта (F5 или заново открыть пульт) |
| Что делает кнопка, новый HTTP-маршрут | `logic.mjs`, `routes` | ничего, следующий запрос возьмёт новую версию |
| Что делает действие агента | `logic.mjs`, `actions` | ничего |
| Новое действие агента, описание canvas | `extension.mjs` и `actions` в `logic.mjs` | новая сессия |

Новое действие объявляется в двух местах: имя и описание в `extension.mjs`, обработчик в `actions` в `logic.mjs`. Обработчики получают `{ session, body }` для HTTP и `{ session, input }` для действий; `session` нужен, например, чтобы открыть вкладку встроенного браузера через `session.rpc.canvas.open`.

## Отладка

Расширение пишет в лог процесса: самый свежий `~/.copilot/logs/process-*.log`, в котором упоминается `roll-panel`. Туда же уходят необработанные исключения, процесс при этом не падает.

`console.log` в расширении писать нельзя: stdout занят протоколом JSON-RPC. Для отладки годится `process.stderr.write`.

В `logic.mjs` не стоит ходить в локальные серверы через `fetch`: встроенный в Node undici падал на ответах страницы Winamp и ронял процесс. Для проверки, жив ли сервер, хватает TCP-подключения к порту.

## Что где хранится

- История диктовки берётся из лога `%LOCALAPPDATA%\Roll\dictation\dictation.log`. Кнопка "Очистить историю" лог не трогает: она пишет момент очистки в `history-cleared.txt` рядом, и пульт показывает только то, что сказано позже.
- Текущую стадию диктовки (грузит модель, ждёт кнопку, пишет звук, готовит звук, распознаёт с процентом по сегментам, печатает) и разбор последней фразы по времени `ptt.py` пишет в `state.json` там же, на каждой смене стадии. Стадия видна справа от кнопок, разбор - строкой под журналом. Пульт спрашивает файл дважды в секунду, пока диктовка запущена. Правки `ptt.py` начинают работать после перезапуска диктовки.
- Страница плейлиста - это `Start-WinampPlaylist` на порту 8731, запущенная скрытым `pwsh`. Она переживает перезапуск расширения.
- Вкладку плейлиста пульт открывает по адресу с `#app`. По этой метке страница снимает с себя зум приложения через CSS `zoom` и выглядит как в обычном браузере при 100%. Без метки, в обычном браузере, зум не трогается.
