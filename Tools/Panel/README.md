# Пульт Roll

Canvas-расширение Copilot: панель с кнопками для страницы плейлиста Winamp, бросков кубиков и голосовой диктовки. Инструменты сами живут в модуле Roll, пульт только вызывает их команды.

## Установка

```powershell
Install-RollPanel
```

На новом компьютере пульту нужны:

- PowerShell 7 (`pwsh`) и модуль Roll в любой папке, импортированный через `Import-Module <папка>\Roll.psd1`;
- для диктовки - Python 3.9 через `py -3.9`, затем один раз `Install-Dictation`: он соберёт venv в `%LOCALAPPDATA%\Roll\dictation`. Ускорение на видеокарте требует встроенной графики Intel с драйвером; без неё диктовка сама работает на процессоре;
- для страницы Winamp - Winamp в `Program Files`, `python` на PATH с пакетом `mutagen` и ffmpeg (`winget install Gyan.FFmpeg` или любой `ffprobe` на PATH).

Пути к модулю пульт и страница Winamp находят сами, относительно своих файлов. Музыка и кампания по-прежнему ищутся в `C:\vaults`.

Команда кладёт в `~/.copilot/extensions/roll-panel` заглушку из одной строки, которая импортирует `Tools\Panel\extension.mjs` из модуля. В заглушке записан полный путь к модулю, поэтому на новом компьютере и после переноса модуля команду запускают заново.

Copilot подключает расширения при старте сессии. Пульт появится в сессиях, открытых после установки; в уже идущей его не будет. Открыть его можно просьбой "открой пульт".

## Файлы

- `extension.mjs` - объявление canvas и список действий для агента. Рантайм читает его один раз, при старте сессии.
- `logic.mjs` - вся работа: статус, запуск и остановка, журнал диктовки, броски. Перечитывается при каждом изменении файла.
- `panel.html` - страница пульта. Читается заново при каждом открытии страницы.

## Как править

| Что меняется | Где | Что сделать после правки |
| --- | --- | --- |
| Вид, кнопки, порядок секций | `panel.html` | обновить страницу пульта (F5 или заново открыть пульт) |
| Что делает кнопка, новый HTTP-маршрут | `logic.mjs`, `routes` | ничего, следующий запрос возьмёт новую версию |
| Что делает действие агента | `logic.mjs`, `actions` | ничего |
| Новое действие агента, описание canvas | `extension.mjs` и `actions` в `logic.mjs` | новая сессия |

Новое действие объявляется в двух местах: имя и описание в `extension.mjs`, обработчик в `actions` в `logic.mjs`. Обработчики получают `{ session, body }` для HTTP и `{ session, input }` для действий; `session` нужен, например, чтобы открыть вкладку встроенного браузера через `session.rpc.canvas.open`.

## Отладка

Расширение пишет в лог процесса: самый свежий `~/.copilot/logs/process-*.log`, в котором упоминается `roll-panel`. Туда же уходят необработанные исключения, процесс при этом не падает.

`console.log` в расширении писать нельзя: stdout занят протоколом JSON-RPC. Для отладки годится `process.stderr.write`.

В `logic.mjs` не стоит ходить в локальные серверы через `fetch`: встроенный в Node undici падал на ответах страницы Winamp и ронял процесс. Для проверки, жив ли сервер, хватает TCP-подключения к порту.

## Что где хранится

- История диктовки берётся из лога `%LOCALAPPDATA%\Roll\dictation\dictation.log`. Кнопка "Очистить историю" лог не трогает: она пишет момент очистки в `history-cleared.txt` рядом, и пульт показывает только то, что сказано позже.
- Текущую стадию диктовки (грузит модель, ждёт кнопку, пишет звук, готовит звук, распознаёт, печатает) и разбор последней фразы по времени `ptt.py` пишет в `state.json` там же, на каждой смене стадии. Стадия видна справа от кнопок, разбор - строкой под журналом. Процента у распознавания нет: Whisper отдаёт текст только после целого 30-секундного окна, а фраза почти всегда укладывается в одно. Пульт спрашивает файл дважды в секунду, пока диктовка запущена. Правки `ptt.py` начинают работать после перезапуска диктовки.
- Пять последних записей диктовки `ptt.py` хранит в `recordings` рядом с логом, старые удаляет сам. На них `Tools\Dictation\bench.py` сравнивает настройки распознавания по времени и по тексту: запускать из venv диктовки, `%LOCALAPPDATA%\Roll\dictation\venv\Scripts\python.exe Tools\Dictation\bench.py --encoders gpu,off --beams 5,1 --threads 0,8`. Замер ноября 2026 на Core Ultra 7: все 8 ядер на 6% быстрее четырёх потоков по умолчанию, один вариант вместо пяти даёт ещё 3%, текст на пяти записях совпал слово в слово. Взяты все ядра, пять вариантов оставлены ради качества.
- Кодировщик Whisper выбирается по железу (`-Encoder auto`, `pick_device` в `Tools\Dictation\ov_encoder.py`). Карта NVIDIA идёт первой: если CTranslate2 её видит и в venv есть cuBLAS и cuDNN (`Install-Dictation` ставит их из `requirements-cuda.txt`, когда находит NVIDIA), вся модель, и кодировщик, и декодер, считается на CUDA в float16 (`Tools\Dictation\cuda_model.py`). На RTX 4090 фраза в 12 с распознаётся за 0.23 с против 3.3 с на 16 ядрах Ryzen 9 7950X3D, текст тот же, цена - 2.5 ГБ видеопамяти. Без NVIDIA при видеокарте Intel Arc кодировщик считается в OpenVINO на ней, без Arc - на NPU, если он есть, иначе в CTranslate2 на процессоре; декодер тогда остаётся на процессоре, потоков у него по числу физических ядер. На Core Ultra 7 с Arc пять записей распознаются за 5 с вместо 42, на 60 фразах FLEURS ошибок 2.2% против 2.6%. Цена - 2.5 ГБ памяти вместо 1 и 0.6 ГБ модели в кэше Hugging Face. Старая встроенная графика UHD не в счёт: на i9-10900K с UHD 630 одно окно кодировщика на ней идёт 7.1 с, а на процессоре 6.1 с, и фраза там распознаётся около 7 с при любом выборе. Устройство видно в пульте под стадией (CUDA, GPU, NPU или CPU), когда диктовка ждёт кнопку, рядом - микрофон по умолчанию, с которого пойдёт запись (полное имя - в подсказке). `ptt.py` перечитывает его перед каждой записью и раз в 3 с в простое, так что смена микрофона в настройках звука Windows подхватывается без перезапуска диктовки. Если автоматика ошиблась - `Stop-Dictation; Start-Dictation -Encoder off` (или `cuda`, `gpu`, `npu`), вернуть автоматику - то же с `auto`. Выбор хранится в `encoder.txt` рядом с логом, поэтому кнопка "Запустить" в пульте его помнит. Если CUDA или OpenVINO не поднялись или упали посреди работы, `ptt.py` сам переходит на процессор, пишет причину в лог, и в пульте под стадией появляется "CPU". Скомпилированный кодировщик OpenVINO лежит в `openvino` рядом с логом, повторный старт берёт его оттуда за 1.5 с.
- Страница плейлиста - это `Start-WinampPlaylist` на порту 8731, запущенная скрытым `pwsh`. Она переживает перезапуск расширения.
- Вкладку плейлиста пульт открывает по адресу с `#app`. По этой метке страница снимает с себя зум приложения через CSS `zoom` и выглядит как в обычном браузере при 100%. Без метки, в обычном браузере, зум не трогается.
